# Patches — the two games, and what has actually been verified

Two patches, one per game. Both are generated by `make_patches.py` from the pinned upstream sources
and checked with `git apply --check`.

| File | Game | Pinned commit | Touches |
|---|---|---|---|
| `veloren-host.patch` | [veloren/veloren](https://github.com/veloren/veloren) | `585a91b4a76fcf5df7a4851127cf5907a3ce34df` (2026-09-30, GPL-3.0) | `voxygen/Cargo.toml`, `voxygen/src/lib.rs`, **new** `voxygen/src/bridge/mod.rs`, `voxygen/src/session/mod.rs` (one hook) |
| `recwars-guest.patch` | [martin-t/rec-wars](https://github.com/martin-t/rec-wars) | `201690250a9a04ea9b9eb36dbec3bd84c211b0cd` (2024-12-28, AGPL-3.0-or-later) | `Cargo.toml`, `src/main.rs`, `src/map.rs` (one constructor), **new** `src/bridge.rs` |

## What is verified, and what is not

Be careful reading "applies cleanly" — it means exactly that.

* **Verified here:** every hunk applies to the pinned commit (`git apply --check`, run by
  `make_patches.py`), the added sources are bracket-balanced after stripping comments and strings, and
  the *shape* of the bridge (protocol frames, region layout, mapping, CRC, watchdogs) is tested
  against the fakes in `../fakes/` — 119 unit checks plus an 11-oracle two-process demo, both passing.
* **Not verified here:** anything that needs a Rust toolchain or a GPU. Neither patch has ever been
  compiled, and neither game has ever been run. Expect to fix small compile errors in the two added
  modules: they were written from reading the pinned sources, not from a compiler. The most likely
  spots are named in "Known rough edges" below.
* The drawing half of the host side (guest entities as sprites, the guest framebuffer on a quad) is
  **deliberately not in the patch**: the patches give you the live, tested data path and mark the one
  place the renderer hook belongs (`Scene::render`'s first pass, `voxygen/src/scene/mod.rs:1552`).
  `../docs/ARCHITECTURE.md` describes how to add it. The fakes implement it end to end, so there is a
  working reference for the pixels — just not inside Veloren.

## How to apply

```sh
# 1. bridge crate — the same crate both games compile
git clone https://github.com/veloren/veloren.git && cd veloren
git checkout 585a91b4a76fcf5df7a4851127cf5907a3ce34df
cp -r /path/to/universal-modder/examples/veloren-recwars-passthrough/bridge ./um-bridge
git apply /path/to/universal-modder/examples/veloren-recwars-passthrough/patches/veloren-host.patch

# 2. the guest
git clone https://github.com/martin-t/rec-wars.git && cd rec-wars
git checkout 201690250a9a04ea9b9eb36dbec3bd84c211b0cd
cp -r /path/to/universal-modder/examples/veloren-recwars-passthrough/bridge ./um-bridge
git apply /path/to/universal-modder/examples/veloren-recwars-passthrough/patches/recwars-guest.patch
```

Run order, environment, and the loopback-only safety notes are in `../README.md`. The short version:
start RecWars first (it listens on `127.0.0.1:47811`), then Veloren with `UM_BRIDGE=1`. With neither
variable set, both games are byte-for-byte the games they were.

## Known rough edges

Named honestly so you know where to look first. None of these affect the fakes or the protocol.

1. **Veloren's terrain reader** (`voxygen/src/bridge/mod.rs`, `ground_height`) uses
   `TerrainGrid::{get_key, get, chunk_key}` plus `TerrainChunk::{get_min_z, get_max_z}`. Those names
   are read off `common/src/terrain/mod.rs`; if a signature has moved, this is the one place to fix.
   A cell whose column is not loaded is exported as *unknown* and the guest treats it as a wall, never
   as a hole.
2. **Camera accessors**: `Camera::dependents()`, `Camera::get_focus_pos()` and the FOV getter are used
   from `bridge::maintain`. The names come from the `session/mod.rs` hook site; a rename is a
   one-line fix.
3. **`is_filled`** on a terrain block needs `common::vol::FilledVox` in scope.
4. **RecWars' frame readback** calls `get_screen_data()` and nearest-box-downsamples it. That is the
   expensive part (10-20 ms at 1600×900, per the game's own comment at `src/client.rs:314`), which is
   why the default publishes every 3rd frame at scale 2. Rendering into a `RenderTarget` and reading
   that back is the documented improvement and is a self-contained change in one function.
5. **RecWars' turret aiming** from `MOUSE` deltas is approximate: a delta turns the turret while it is
   non-zero. The host's own input path in Veloren does the same thing for now.
6. **Cross-machine play is not a goal** and the crate does not pretend otherwise: the control socket
   binds `127.0.0.1`, and there is no authentication. Both games run on one machine, as in the
   reference Minecraft × GTA V mod. Do not expose the port.

## Regenerating

```sh
python3 patches/make_patches.py     # needs the recon clones at /home/user/recon/{veloren,rec-wars}
```

If the recon clones are missing, clone them at the pinned commits — the script tells you so and exits.
The two modules' source of truth is `patches/files/*.rs`; the patches are generated, never hand-edited,
so a regenerate can never drift from what was reviewed.
