# Ultimate World Cup 26

A complete, self-contained World Cup football game that runs in a browser tab. No install, no build step, no
downloaded assets: the flags, kits, crowd, stadium, commentary and every sound effect are generated by code.

**Play it:** open `index.html` with any static server.

```bash
python3 -m http.server 8000            # or: npx serve .
# then visit http://localhost:8000
```

ES modules need a real HTTP origin, so double-clicking the file will not work (`file://` blocks module imports).

---

## What's in the box

| | |
|---|---|
| **32 nations** | real teams, real confederations, procedurally generated squad names, per-player attributes, hand-drawn vector flags |
| **Road to the Final** | pot-seeded group of 4, then R16 → QF → SF → third place → Final. Everything you do not play is simulated with a Poisson model, and the other 31 nations carry form between matches |
| **Quick Match** | pick any two nations, knockouts optional |
| **Penalty shootout** | standalone mode, or the real end of a tied knockout: aim with the stick, hold to power, and *you* keep net when the other side steps up |
| **Match engine** | passing, through balls, lobbing, sprint + stamina, slide tackles, fouls, yellow/red cards, throw-ins, goal kicks, corners with a defensive wall, free kicks, penalties, keeper AI that catches, smother or parry, extra time |
| **Presentation** | procedural stadium bowl with per-venue crowd colours, LED boards, mown stripes, kit patterns (stripes, hoops, halves, sash, checks), automatic away-kit change when two nations draw too close, ball physics with bounce and curve, net ripple, screen shake, confetti, goal banner with both flags |
| **Sound** | WebAudio synthesis only: kick, pass, net, post, whistle, crowd bed that swells when the ball is in the box and roars for a goal |
| **Controls** | keyboard, XInput gamepad, and a touch thumb-pad + buttons that appear automatically on phones |
| **Persistence** | settings and an in-progress tournament are stored in `localStorage`, so a refresh resumes the cup |

## Controls

| Action | Keyboard | Gamepad |
|---|---|---|
| Move | `WASD` / arrows | left stick |
| Shoot (hold to charge) | `Space` | RT |
| Pass | `J` / `Z` | A |
| Through ball / cross | `K` / `X` | X |
| Slide tackle / block | `L` / `C` | B |
| Switch player | `Q` | Y |
| Second man presses | `E` | — |
| Sprint | `Shift` | LT / RB |
| Pause | `Esc` / `P` | — |

You always control the player nearest the ball. On a set piece you are taking, aim with the stick then press
`Space` to play it (a direct strike from a dangerous free kick), `J` to play short, or `K` to whip it into the
box. In a shootout, if the other side is kicking, move to guess a side and press `Space` to dive.

## Testing without a browser

The engine has no DOM dependency, so the whole thing is testable in node:

```bash
node tools/smoke.mjs full      # 16 fixture pairs, full matches with extra time and shootouts
node tools/smoke.mjs quick      # short smoke of the engine contract
node tools/smoke.mjs tourney    # a whole tournament, group to final
node tools/render-smoke.mjs    # presentation + integration (DOM stubbed): every screen, HUD wiring,
                               # kit clashes, save/restore, a whole cup played by a scripted
                               # synthetic international, and a tied knockout that goes to penalties
node tools/preview.mjs preview  # renders real match frames + a flag/kits sheet to PNG
```

`tools/preview.mjs` needs `@napi-rs/canvas` (dev only, and deliberately not a dependency of the game):
`npm i @napi-rs/canvas`, or run it against a copy in a scratch folder. It is the closest thing to a screenshot
pipeline this project has, and it is how the layout was tuned for 390 px portrait up to 4K. Its output folder is
git-ignored; the harnesses in `tools/` are kept in the repo on purpose, they are the only regression net a
browser game without a browser can have.

## Layout

```
index.html          shell: canvas + two DOM layers
styles.css          everything you see that isn't drawn to the canvas
src/flags.js        the vector flag DSL (rects, stripes, crosses, stars, polygons)
src/teams.js        the 32 nations: kits, ratings, flag specs, squads, 8 real venues
src/match.js        the match engine: physics, AI, set pieces, cards, shootouts
src/tournament.js   draw, group tables, knockout bracket, Poisson simulation
src/render.js       canvas renderer: stadium, kits, ball, effects, banners, camera
src/audio.js        WebAudio synth (no files)
src/input.js        keyboard + gamepad + touch folded into one state object
src/ui.js           DOM screens: title, team pick, hub, tables, bracket, HUD, cards
src/main.js         the app shell: loop, modes, sound cues, saving
tools/              headless tests and the preview renderer
```

Everything is plain ES modules. There is no bundler, no framework, no `node_modules` for the game itself.

## Tuning

- `src/teams.js` → `RAW` is one line per nation: `id, name, nickname, confed, jersey, shorts, pattern, trim,
  ratings, surnames`. Add a line, add a flag to `F`, and it appears in the draw, the pick screen and the sim.
- `src/match.js` → `DIFFICULTY` (reaction time, AI skill, aggression, pressing, keeper quality) and `P`
  (pitch geometry). `MIN_PER_SEC_BASE` sets how many match minutes pass per real minute.
- `src/tournament.js` → `xgFor()` / `poisson()` control how believable the simulated scorelines are.
- Balance is measured, not guessed: `tools/smoke.mjs full` prints goals, shots, fouls and cards per match for 16
  pairs on every run.

## Known limits

Deliberately left out: offside, crossbar collision beyond the post bounce, substitutions, throw-in animations.
Shot accuracy comes out higher than real football (~80% on target vs ~40%) because the model measures the
crossing point rather than deflection chaos — it is an arcade game on purpose.
